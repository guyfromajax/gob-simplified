Branch `app/prep-v2-pr3`, off `origin/develop` (`3c21242ca`). The sim engine, `cpu_week_pool`, `sim_rng`, and `finalize` were not touched. Scouting stays `#coaches-tab`. PR 4 was not started.

## Plan

Playbooks is a panel inside the franchise command center, the same way Training, the training report, and Game Plan already are. `playbooks.html` stays the source of the markup and the behavior.

The view fetches the page with `?embed=1`, parses it with `DOMParser`, and imports the container plus the toast. Scripts in that HTML do not run. A redirect at the top of `playbooks.html` returns immediately when `embed=1` or `mode=tutorial`. Otherwise the URL `location.replace`s onto `?tab=playbooks-view` and keeps the query.

`playbooks.js` stays a classic file. It is not wrapped in the source. The command center already declares `let franchiseId`, so a plain script tag is rejected. The view fetches the file and runs it inside an IIFE. `window.initPlaybooks` is what the view awaits. On a standalone `embed=1` load, `DOMContentLoaded` still calls it.

`GOBViews.show` waits for the mount. The view does not unmount on hide, so weights, the open play, and the call-sheet order survive a Prep tab switch. Switching Playbooks to Game Plan took 21ms. `performance.timeOrigin` did not change and there was still one navigation entry.

The Prep underline opens `playbooks-view`. `?tab=playbooks-tab` canonicalizes to the view. `/playbooks.html` redirects there. `PREP_EDITOR` is gone; Playbooks no longer leaves the command-center document. The old `#playbooks-tab` summary panel stays in the markup and is not a route.

## Playbooks

Rows are `.play`, grouped by Motion, Set Plays, Fast Breaks on offense and Man, Zone, HC Traps on defense. Each row is name + meta (focus / target shooter / top scorer), a weight bar and %, a CMD number, and the call-sheet slot badge or "+". CMD is a column header on the section. It is not repeated on the row. A play on the call sheet is navy (`.play.on`). Coming Later rows (`isActive === false`) render `.play.lk`.

Clicking a row opens `.pdet` in place. The sentence is `copy.copy_1` from GET `/api/playbooks` when the play document has it. If it is absent, there is no sentence line. The detail also shows weight, CMD, focus or target shooter, top scorer, and the call-sheet slot. Weight editing stays on the bar and the % input. Motion focus, target shooter, and lock stay in the detail. The save payload, validation, and weight arithmetic are unchanged.

The call sheet is sticky `.csr` beside the list: slot number, drag grip, name, weight, CMD, all navy. Remaining room is one dashed "N open" filler. Cap is still 8 offense + 8 defense. `togglePcc`, the slot ×, drag-reorder, and the `pc_order` payload are the existing ones. Fast Breaks and HC Traps still cannot join the sheet.

Tab-row tools: Offense/Defense segment (neutral white selected), the "N of 2 flexible sections balanced" check, and orange Save Playbooks. Save is enabled exactly as today (both flexible totals = 100). After a successful save inside the view, the page stays on the view.

The live shot-weight strip stays on top. Colour scaling and thresholds are still `getPswColor` in `common.js` (blue >35, green ≥21, gold ≥11, red below).

## Backend

GET `/api/playbooks` adds `copy.copy_1` on each motion and set-play summary when the play document has a non-empty `copy_1`. Team snapshots omit that field, so the handler also reads the catalog play by id or name. If it is still absent, the key is omitted.
