# Prep v2 PR 2 — Training and Training Report as views

Branch `app/prep-v2-pr2`, off `origin/develop` (`d3da2a517`). The sim engine, `cpu_week_pool`, `sim_rng`, and `finalize` were not touched. Playbooks stays a page. Scouting stays `#coaches-tab`. PR 3 and PR 4 were not started.

## Plan

Training, the training report, and Game Plan browse are panels inside the franchise command center. The classic pages stay the source of the markup and the behavior.

Each view fetches its page with `?embed=1`, parses it with `DOMParser`, and imports the container nodes. Scripts in that HTML do not run. A redirect at the top of `training.html`, `training-report.html`, and `game-plan.html` returns immediately when `embed=1`. Otherwise those URLs `location.replace` onto the matching command-center tab and keep the query. `game-plan.html` does not redirect when `resume_from_timeout=true` or `mode=tutorial`. No caller uses `training.html?mode=tutorial`. The Training Tutorial button goes to `/tutorial-training.html`. The `mode=tutorial` guard is in the redirect anyway, so a future caller would not be swallowed by the view.

The page scripts stay classic files. They are not wrapped in the source. The command center already declares `let franchiseId`, so a plain `<script src="/training-report.js">` (and `game-plan.js`) is rejected. The view fetches the file and runs it inside an IIFE. Bindings stay local. Anything the script assigns to `window` still lands. `training.js` starts itself at the bottom. `training-report.js` calls `startTrainingReport()` when the document is already loaded. `game-plan.js` exposes `window.initGamePlan` so it does not overwrite the command center's `init`, and the view awaits that call before the save button is placed.

`GOBViews.show` waits for an async mount. It does not unmount on hide, so stepper values and Game Plan stops survive a tab switch. There is no discard warning on that switch. `GOBNav.warnOnLeave` still warns when leaving the command-center document if training is dirty.

Opening custom playbooks from the training view is another step in the same flow. `GOBNav.go` does not move the flow start or the return-reload mark when a flow is already open. The start stays the Office entry from Run Training, so Back to Office still jumps there and one browser Back reaches mode-select. A `history.go` that runs after the document is complete is synchronous. Deferring it let the report's already-enabled Advance satisfy the Back wait before the jump to the Office started.

What stays where it is: the Player Maximizer modal and the Auto-Train modal are document overlays imported with the training container. Tutorial lesson pages stay separate. Playbooks stays `/playbooks.html`. Scouting stays `#coaches-tab`. `game-plan.js` still owns `pageLoadParams`, `game_id`, and the tutorial recovery. `common.js` and `API_CONFIG` stay page globals. The old `#training-tab` summary panel stays in the document and is not a route.

The Prep rail opens `training-view`. The underline for a report is still Training. `?tab=training-tab` and `?tab=game-plan-tab` canonicalize to the views. Office Run Training still goes to `/training.html`, which then replaces onto the view, so the existing "go to training.html" assertions hold.

## Advance

`GOBAdvance.setOverride` / `clearOverride` paint the top-bar button and ignore a later `updatePlayButton` refresh. The override is set only while `training-view` is the tab: label Submit Training, enabled when points remaining are 0, a focus is chosen, and `isPlayerMaximizerSubmitReady()`. It runs the existing submit and does not play the Advance confirm. The body `#submit-btn` is removed before `training.js` loads, so there is one green button.

`training-report-view` does not set an override. The top bar stays the normal Advance from `updatePlayButton` (Run Training while the week is open, Play Next Game once it is committed).

## Training

Budget comes from `training_points` (30 in camp, 24 in season). The range inputs stay the model and stay focusable. The visible control is a six-stop `.ps` stepper. Pips are `aria-hidden` buttons. The focused range draws the ring on the stepper.

The requirements bar, Auto-Train, and Training Tutorial sit in the tab-row tools. Auto-Train and Training Tutorial are ghost buttons. The page header is hidden inside `#training-view`. Breaks and Scrimmages stay hover tips. The playbook segment is unchanged. Choose Attributes still opens the existing Player Maximizer modal.

Player Development is a table in the view (`opts.layout === 'table'`). The command-center summary keeps the card grid. Portraits are 28px (recruit image when `portrait_source === 'recruit'` and `image_id` is set, otherwise the usual player image, monogram on error). Jersey, position, and the current-to-potential RT letters come from the server. Position and focus tallies are server counts, including zeros, and a local position or focus save adjusts those maps instead of recounting the client.

On a 1280×720 viewport the three drill columns ended at y=626. Coaching Focus starts at the bottom edge. Player Development scrolls.

## Training report

Section order is Notes, Team, Players, Projected Starting 5, Playbook. The brief line stays "Week N Training Brief · For Coaching Staff Only".

Opened from training, the old green Go To Locker Room is a ghost Back to Office in the tab-row tools. It still `exitFlow`s through `resolveFranchiseLockerRoomUrl` with `tut_alert=training_return`. Opened with `from=news` or `from=inbox`, that button is hidden and the report shows the standard `← News` up-link (`a.gob-dt-up`, `data-gob-up`) back to `news-view`, which restores the feed scroll.

A successful franchise submit sets `sessionStorage` `gob_training_return` to the franchise id. The Office consumes it once, on first mount: full load via `onFccDomReady`, or an in-document rail click via `gob-tab-shown` on `home-tab`. Landing on the report does not consume it. Back to Office still passes `tut_alert=training_return`, and the counter increments once if both the flag and the param are present. The flag is cleared only when the Office is the current surface.

Attribute and team deltas stay ▲/▼ in `--text-100`. A real zero stays "No change" in `--text-38`. A non-zero cell gets an inset `--text-60` ring. Triple-up is not blue. Team rows still print every key the report already prints, and `shot_threshold` still treats a lower raw number as the better direction. The playbook summary is a table of play, section, CMD, and change. Weight, side, and the momentum bars are gone.
