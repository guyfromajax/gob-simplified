## Part 1 — the persistence gate: CLEAN. Turns never reach Mongo.

**The written document grows +0.45%, carries 0 turns in every state, and sits at 0.61% of the 16 MB cap.** Nothing is written that a played game does not already write.

### 1. What the CPU-sim path actually writes

The path a simmed week runs is **`franchise_routes._run_franchise_cpu_full_simulation_core`** (`franchise_routes.py:6216`), dispatched per game through `cpu_week_pool.simulate_cpu_week_pooled` → `_worker` (`cpu_week_pool.py:141-161`) when `FRANCHISE_CPU_SIM_USE_POOL=1`, or `_run_sequential_inprocess` (`:199-211`) otherwise. Both call the same core and return the same `(away, home, summary)` shape.

| step | file:line | what |
|---|---|---|
| the sim core's last act | **`franchise_routes.py:6305`** | `summary = summarize_game_state(gm)` |
| the write | **`franchise_routes.py:8560`** | `db.games.update_one({"_id": computer_game_id}, {"$set": summary}, upsert=True)` |
| collection | **`db.games`** | keyed on a generated `computer_game_id`, plus `franchise_id` and `week` stamped at `:8556-8558` |

**It is neither `game_manager.to_dict()` nor `build_game_summary()`.** `to_dict()` does include `"turns": self.turns` (`game_manager.py:237`) — that is what made the risk worth checking — **but the CPU-sim path never calls it.** `build_game_summary` (box_score only) is the *user-game* summary builder, called from `api.py:151`, and is likewise not on this path.

**The decisive line is `shared.py:3002-3003`**, inside `summarize_game_state`:

```python
# For database saves, don't store turns at all (only need game state metadata)
# Turns are only needed for real-time frontend display, not for persistence
if exclude_animations:
    turns = []  # Empty array - don't save turns to database (prevents document size issues)
```

`summarize_game_state` defaults `exclude_animations=True`, and the CPU-sim core calls it with the default. **So `animation_steps` and `animations` are dropped before the write, by design, with a comment saying exactly why.** The field survives in the document as `"turns": []`.

**The written document is at 0.61% of the cap at its maximum** (103,214 bytes). Nothing approaches it.

If that response is ever persisted or cached whole, it would fail regardless of B1-A — worth its own look, not this one.

**Gate verdict: clean. Proceeding to Part 2.**

### 8. The two substitute flags — kept, and their guards re-scoped

**Kept, not deleted, and I think that is right.** They are no longer redundant code: they are the machinery that makes the kill switch *work*. With B1-A off, the sim arm has no `animation_steps`, and `_write_sim_hco_placement_coords` / `apply_sim_crash_destinations` are what put coordinates on the players. Delete them and `GOB_SIM_BUILD_ANIM_FOR_EMITTER=0` stops reproducing `ec4f5acfc_poslookup2` — the rollback path dies with them. They cost nothing while dormant (both return 0 on the first line when the turn carries steps).

**The three guards are re-scoped by pinning the configuration they describe, not by skipping.** An autouse fixture in each file sets `GOB_SIM_BUILD_ANIM_FOR_EMITTER=0`:

```python
@pytest.fixture(autouse=True)
def _b1a_off(monkeypatch):
    monkeypatch.setenv("GOB_SIM_BUILD_ANIM_FOR_EMITTER", "0")
```

A `skipif` would have removed the coverage entirely; this keeps all 23 tests in `test_sim_crash_apply.py` + `test_sim_hco_coord_write.py` running, against the arm state they were written for. **No assertion was touched.** Without it they failed honestly — `AssertionError: the guard measured too few overlay players to mean anything`, `assert 0 > 50` — because their subject is dormant under the new default.
