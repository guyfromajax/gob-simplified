## 4. "All changes"

- **Root cause.** The Office built the link's `team_id` only from its own address (`location.search`). The app opens the Office with `franchise_id` alone after a game (`gobNav` exit), from the mode select, from Set Lineup and from team select, so the link went out as `/training-report.html?mode=franchise&from=office&franchise_id=…&week=N` with no team. `training-report.js` stops before fetching when it has no `team_id` ("mode and team_id are required"), so the page sat empty.
- **Why tests missed it.** The existing test (h) opens the Office with `team_id` in the address, which the real app usually does not.
- **Fix.** `officeHome.js` `userTeamId()`: the address first, then `GOBViews.userTeamId()` (the franchise's own team, which the command center records as soon as its data is in). Used by the five Office link builders that read the team the same way, so the standings, box-score and recruiting links carry it too.
- **Test.** `training-advance-focus.spec.js` **h2**: opens the Office with `franchise_id` only, clicks "All changes", and requires the report itself (week 12, the title, its content, no failure card) and a `/franchise/training-report` request with the team id. Fails on the old code.
