## mongomock decision: moved to dev
All four imports are **inside functions**, never at module top level:
- **`persistence/mongo.py`:** only when `GOB_DB_MODE=mongomock` (tests).
- **`script_db.py`:** only in mongomock mode, which requires `ENVIRONMENT=test`.
- **`persistence/sqlite.py`, remote collections:** only when `environment == "test"`.
- **`persistence/sqlite.py`, EOG band log:** the one non-test path. On desktop (non-test) with **`GOB_EOG_BAND_ENABLED=1`**, it holds the EOG log in an in-memory mongomock collection so it never enters the save.
  - The flag is **opt-in**. Nothing in the repo, the desktop app, `loopback_env` or `compile_loopback.sh` sets it.
  - The Nuitka desktop build bundles only what's installed in the build interpreter.

**What I did:** moved `mongomock` to `requirements-dev.in`, and made the EOG import lazy-safe. With the flag set and mongomock absent, a desktop build now logs a warning and uses `NullCollection` (no EOG log) instead of failing at store construction.

**Default behaviour is unchanged.** With the flag unset, mongomock is never imported. Three tests cover it:
- with the flag set and mongomock installed, it logs
- with the flag set and mongomock missing, you get `NullCollection` and a warning, not a crash
- with the default flag, mongomock is never imported, even when it's unavailable

**If you want EOG calibration on a desktop beta build,** install `requirements-dev.txt` in the desktop build interpreter, or add `mongomock` back to `requirements.in`. It's a one-line change.

## How to upgrade a package going forward
1. Edit `requirements.in`, or `requirements-dev.in` for test-only deps. To upgrade one package: `pip-compile --no-strip-extras --upgrade-package <name> --output-file=requirements.txt requirements.in`.
2. Recompile `requirements-dev.txt` from `requirements-dev.in`, **under Python 3.11**.
3. Run the full suite in a 3.11 venv built from `requirements-dev.txt`.
4. Commit the `.in` and both `.txt` files **as their own PR**.

**Never hand-edit a `.txt`.** This is also in CLAUDE.md "Dependencies".
