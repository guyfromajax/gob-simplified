## Backend fields added

Standings rows (`GET /franchise/standings`, still `@browse_cached`). Existing keys are unchanged, including `pct`, `differential`, and the rank-prefixed `next` string. Added on each row:

- `primary_color`
- `streak` (`W3` / `L1` / `""`). Ties clear the streak. Not part of `standings_display_sort_key`. One sort.
- `next_opponent_id`
- `next_opponent_name`
- `next_week`
- `next_site` (`vs` or `at`)

Added on the response when `team_id` resolves:

- `user_conference`
- `user_region`

`scope=user_region` is unchanged (user conference plus sister conference). New filters, applied after that single sort:

- `scope=conference` — that conference number
- `scope=region` — that region

The view requests the unscoped list (`franchise_id` + `team_id`, no `scope`) and filters Conference / Region / National in the page from `region` and `conference`. Conference also requires the user's region, so a repeated conference number in another region is not "Yours".

Leaders (`GET /franchise/leaders`). No new top-level keys. Omitted `basis` keeps the previous values (PTS/REB/AST per game, other counting stats as season totals, percentages unchanged). Added query:

- `basis=per_game` — every counting stat divided by GP, using the existing divide pipeline
- `basis=totals` — counting stats left as sums

Percentages ignore `basis`. Added on each player row:

- `team_id`
- `position`
- `year`

Added only on season `FG%` and `DEF%` rows:

- `qualification_caption` — `"min 5 FGA per team game"` and `"min 6 DEF_A per team game"`, from `LEADER_QUALIFICATION_FLOORS` and `ATTEMPT_FIELDS`. Career rows do not get it.

Team stats (`GET /franchise/team-stats`). Rates attached in Python after aggregation, on each team's `stats` object. `null` when attempts are 0. The view does not divide.

- `FG_PCT`
- `TP_PCT`
- `FT_PCT`
- `SCR_PCT`
- `DEF_PCT`

No new query operator. Streak, next opponent, and the rate fields are derived in Python from documents the routes already load. `basis` only selects the existing per-game or totals pipeline. Those shapes stay on the SQLite adapter because they do not add an operator the adapter has to compile. This pass did not boot `GOB_PERSISTENCE=sqlite`.

## Leaders controls

- Conference / National map to `view_scope=conference|national`. Both already worked. The API also has `view_scope=region`; that control is not shown.
- Per game / Totals map to `basis=per_game|totals`. The view always sends `basis`. Per game is the control default, so 3PTM, BLK, and STL are per game on first open. Other clients that omit `basis` still get the old totals for those stats.
- FG% and DEF% captions are `qualification_caption` from the row. `leadersView.js` falls back to the same two strings only when a row lacks the field.
- "Full list →" `replaceState`s `leader=<stat>` on the same command-center URL and requests `limit=50`. Back leaves the view. A Board control clears the param.

## Follow-up

Merged `origin/develop` (the leaders week snapshot) into `app/t1-tables`. `get_leaders` and `GET /franchise/leaders` both rank through `rank_lines` in `BackEnd/utils/leaders_snapshot.py`. The snapshot path wins when the week lines are fresh; the live scan uses the same ranker. The old eight-aggregate pipelines are gone.

Response shape is only additions. Omitted `basis` still means PTS/REB/AST per game and the other counting stats as totals. `basis=per_game` divides every counting stat by GP. `basis=totals` leaves counting stats as sums. Percentages ignore `basis`. Each row now also has `team_id`, `position`, and `year`. Season `FG%` and `DEF%` rows also have `qualification_caption` (`min 5 FGA per team game`, `min 6 DEF_A per team game`). Career rows do not. No new category keys.

`position` and `year` are appended after the stat blocks, so season PTS stays at index 7. A stored line shorter than that width is treated as stale and rebuilt. Class year is stored as the UI abbreviation (`senior` → `SR`) via `format_player_year_abbrev`, on both the Mongo line and the SQLite tuple line. Empty stays empty.

`tests/test_leaders_snapshot.py` compares the live scan and the snapshot for `basis=per_game`, `basis=totals`, and the new row fields. ### Design

Matched the handoff frames `t1-leaders-1280`, `t1-standings-1280` / `1920`, and `t1-team-stats-1280`.

Leaders cards: category title in the display face, stat and basis on the right (`PTS · per game`). Rank 1 is the hero: initials circle, name, `Team · POS · YR`, display numeral with a unit (`PPG` / `RPG` / `APG` / `SPG` / `BPG` / `3PM`, `%` for percentages). Ranks 2–5 are compact rows (rank, name, three-letter team, display numeral). The user's players are navy, including the hero. `qualification_caption` sits under the FG% and DEF% headers. `Full list →` is 12px and right-aligned.

PCT is three decimals with the leading zero stripped (`.833`, `.500`, `1.000`).

DIFF is the frame's neutral bar: a `--dsz-40` by `--dsz-6` track (`--white-4`), a centre tick (`--white-25`), and a bar that grows left or right from zero, scaled to the max `|diff|` in the visible set. Positive fill is `--white-55`, negative fill is `--white-25`, and the negative numeral is `--text-60`. Green stays on Advance only.

The collapsed rail at 1280 was opening the label's `max-width` immediately while the face stayed 64px for 400ms and the label opacity stayed 0. `nav.rail` is `overflow: visible` and has a view-transition name, so that overflow could be snapshotted past the icons. The hover `max-width` delay is now `400ms, 400ms`, on the same clock as the face. `t1-tables.spec.js` asserts that on Standings, Leaders, and Team Stats at 1280 no collapsed rail label has opacity above 0.05, a box wider than 1px, and a right edge outside the rail face.

Two sub-tabs looked selected because `.stab:hover` (`--white-11`) is stronger than `.stab.on` (`--white-9`). The pointer was moved into `.main` before every screenshot and before the rail check, so only the current view's tab reads as active. The test also expects exactly one `#gob-subtabs .stab.on`.

The conference title (`A1 CONFERENCE · Yours`) is 16px display, tracking 8, `--text-87`. `Yours` is 10px body, tracking 8, `--text-60`. Team Stats group labels match the frame's group row: 10px, tracking 10, `--text-38`, height `--dsz-22`, centered. They had been inheriting the 12px column-header face.
