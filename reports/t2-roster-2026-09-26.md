# T2 — Roster and Team Attributes — 2026-09-26

Branch `app/t2-roster`, off `develop`. Roster and Team Attributes are module views. Attribute tiles are a luminance fill with a tier-colored digit, in the shared tile component.

## Views

Team sub-tabs are Roster, Player Stats, Team Attributes, Schedule. There is no Development tab.

`team-roster-view.html` redirects to `franchise-command-center.html?tab=roster-view` and keeps the query string, the same way rankings does. `?tab=roster-tab` opens Roster. `?tab=team-stats-tab` opens Team Attributes. The old panels stay in the page. Standings and Office links keep the page's `team_id` as the user team and put the viewed team in `roster_team_id`.

Roster reads `GET /roster/{id}`. The browser does not recompute position or RT. Varsity defaults to lineup order (starters, then bench by name). Practice Squad defaults to RT descending. Any column sort drops the Starters / Bench dividers. The header repeats every 16 player rows and is not sticky. Clicking a player opens `player-detail.html` and stores the visible ids in `sessionStorage` key `gob-view-roster-order`. The varsity / practice choice is `gob-view-roster-scope`. Both are documented in UX System §14.

Team Attributes reads `measures` and `updated_after_week` from `GET /franchise/team-data`. It does not invent a scale. A meter renders only when `meter_pct` is set. A delta chip renders only when `delta` is set. The "Updated after Week N" line renders only when `updated_after_week` is set.

## Fields added

Roster player, stamped on the existing roster route:

- `position` — same rule as leaders (`_roster_position`)
- `rt` — `roster_rt` (max position rating)
- `starter` — true when the player is in `projected_starting_five`
- `lineup_order` — index in that lineup, otherwise null

Team-data:

- `measures[]` — `family`, `family_label`, `key`, `label`, `value`, `scale_max`, `meter_pct`, `delta`, `description`
- `updated_after_week` — the closed week of the prior office snapshot, or null

Rows: `team_chemistry` Chemistry (scale 25), `fight` Fight, `discipline` Discipline, `shot_threshold` Shooting, `rebound_modifier` Rebounding, `defensive_efficiency` Defensive efficiency. Families are `character` / Character and `floor` / On the floor.

Left out on purpose:

- `description` is always null. The frame sentences were sample copy.
- Fight, Discipline, Shooting, Rebounding, and Defensive efficiency have no stored max, so `scale_max` and `meter_pct` are null. Shot threshold is not 0–100. Rebound modifier is a 0–1 float.
- `team_chemistry` is not in `TEAM_MEASURE_KEYS`, so a week snapshot does not carry it and its `delta` stays null.
- Dev focus is the existing `training_focus` / `resolved_training_focus`. Other teams omit it. The view does not invent "Not set".
